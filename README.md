# 虚拟机备份维护台

基于 FastAPI 的快照链维护工具：值班员从网页导入 JSON 备份清单（基盘 + 可分叉的增量快照），
可以撤除有子层的非根快照（只重写直接子层），并从任一可用快照下载还原后的原始磁盘镜像。

## 快速开始

```bash
docker compose up --build
# 打开 http://localhost:8000
```

网页操作：「载入示例清单」→「导入」→ 在快照树上点「撤除」或「下载镜像」。
「载入坏块演示场景」会先合法导入一份清单，再篡改卷上层文件制造静置损坏（短块/非法 Base64），
用于演示坏块拦截：下载拒绝、撤除拒绝与覆盖后可恢复的区别。

本地开发（不用 Docker）：

```bash
pip install -r requirements-dev.txt
python -m pytest tests/ -q          # 跑测试
DATA_DIR=./data uvicorn app.main:app --port 8000
```

## 数据模型

- 单盘 ≤ 16 MiB，盘块 4 KiB，清单中块数据为 Base64（解码后必须正好 4096 字节）。
- 清单 `{"disk_size": N, "layers": [{"id", "parent", "blocks": {"块索引": "base64"}}]}`，
  构成一棵（或多棵）快照树；块索引从 0 到 `disk_size/4096 - 1`。
- 稀疏语义：某快照在某块上没有数据时向父层继承；**显式写入的全零块视为改写**，会盖住父层数据。
- 存储布局（`DATA_DIR`，容器内为 `/data` 卷）：

```
manifest.json    当前清单：epoch、disk_size、每层 {parent, file, blocks}（原子替换更新）
journal.json     撤除操作的两阶段日志，仅在操作进行中存在
layers/<uuid>.layer   每层一个文件：{"blocks": {"索引": "base64"}}
```

层文件按 uuid 命名、写一次后不再修改；撤除产生的新子层写为新文件，绝不就地改旧文件。

## 撤除（remove）语义

目标必须是非根且有直接子层的快照。对每个直接子层 C：

```
新C.blocks = C.blocks ∪ (目标.blocks 中 C 没有的块)   # 缺块才继承；全零块算改写，保留子层版本
新C.parent = 目标.parent
```

孙层及更远的层完全不动。可证明每个保留恢复点还原出的字节与撤除前一致：
对任意块，若子层自有 → 仍是子层的值；否则若目标层有 → 合并后取目标的值；否则继续向祖父层继承。

## 坏块（层文件静置损坏）语义

层文件仍是可读 JSON，但其中某个盘块的 Base64 非法、或解码后不是正好 4 KiB 时，该块判为**坏块**。
导入接口始终严格校验，坏块无法通过新导入进入系统；坏块只可能来自卷上的静置损坏，
维护台在每次读层文件时逐块严格校验（带 mtime/大小签名的缓存，外部篡改也能即时识别）。

- **下载拒绝，禁止补齐**：恢复点沿父链解析时，只有确实需要读取某个坏块、且没有任何下层
  用自有块覆盖它，才返回 400 并指明**来源快照与块号**；绝不用更早祖先的好块或零块补齐，
  因此不会再产出短镜像。坏块已被下层自有块覆盖（**显式全零块也算覆盖**）、或位于无关分支时，
  不影响该恢复点下载，镜像长度严格等于盘大小。
- **撤除前置拦截**：撤除在写任何新层文件之前先做只读坏块检查——
  - 任一直接子层自身含坏块 → 整次拒绝；
  - 被撤除层含坏块，且任一直接子层在该块号上没有自有块（会被迫继承坏块）→ 整次拒绝。

  拒绝时不写任何文件、不建 journal，原快照树与层文件逐字节保持原样。
  只有全部直接子层都完好、且覆盖了被撤除层的每个坏块时才允许撤除；
  此时坏块不会进入合并结果，保留恢复点的镜像与撤除前逐字节一致。
- **维护页展示**：每层标注坏块块号；因坏块不可撤除的快照按钮置灰并显示阻断原因
  （来源快照 + 块号）；下载被拒时消息区同样显示来源快照与块号。
- 演示接口 `POST /api/demo/corrupt`：合法导入演示清单后注入三处损坏
  （`base` 块1 短块；`mid` 块2 短块、块4 非法 Base64），对应覆盖/未覆盖两种情形。

## 一致性与崩溃恢复

撤除按以下顺序执行，**第 3 步是唯一的提交点**：

1. 为每个直接子层写出合并后的新层文件（tmp + rename + fsync）——失败则清理半成品，旧链未受影响；
2. 写 `journal.json`（旧/新 epoch、新文件、待删旧文件、完整新清单）；
3. 原子替换 `manifest.json` —— 提交点，失败则回滚（删新文件与 journal），旧链仍可用；
4. 删除旧层文件与 journal（收尾失败不影响一致性）。

进程中断并重启后，启动恢复保证网页只呈现一套完整可恢复的链：

| 现场 | 判定 | 动作 |
|---|---|---|
| journal 有效，manifest 仍是旧 epoch | 崩溃在提交点前 | 回滚：删新文件，保留旧链 |
| journal 有效，manifest 已是新 epoch | 崩溃在提交点后 | 前滚：补删旧文件 |
| journal 缺失/损坏 | 无在途操作（日志先于清单写） | 清理孤儿/临时层文件 |

恢复事件会在网页顶部展示。导入同样原子：新层文件全部落盘后才替换 manifest，
崩溃残留由启动时的孤儿清理回收。

## API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/` | 维护网页 |
| GET | `/api/state` | 当前链状态（层、父子关系、可撤除标记、恢复事件） |
| GET | `/api/sample` | 生成一份示例清单 |
| POST | `/api/demo/corrupt` | 搭建坏块演示场景（合法导入后注入层文件损坏） |
| POST | `/api/import` | 导入清单（整体替换，原子切换） |
| POST | `/api/remove/{id}` | 撤除有子层的非根快照（坏块会被前置拦截） |
| GET | `/api/download/{id}` | 下载该快照还原出的原始镜像（`.raw`）；需要读坏块时 400 拒绝 |

`tests/` 共 76 个用例，覆盖：导入校验（尺寸/索引/base64/环/重复）、各层还原字节与独立解析器一致、
全零块改写、稀疏继承、撤除后字节不变与重挂链、只重写直接子层、提交点前/后崩溃恢复、
写盘失败回滚、孤儿文件清理、API 全流程与错误码，以及坏块专项（短块/非法 Base64 识别、
下载拒绝与来源块号、下层覆盖与显式全零覆盖、撤除继承拦截与原样保持、覆盖后可撤除且字节一致、
进程存活期篡改的缓存失效、重启后拦截依旧生效）。

## 已知限制（后续工作）

- 单进程 + 内存锁，未做多实例并发；层文件为 JSON 存 base64，未做二进制压缩/去重；
- 撤除仅限“有子层的非根快照”，不支持删除叶子快照与整树删除；
- 清单体积未设上限（16 MiB 盘 × 层数的 base64 全量提交），大清单导入会占用较多内存；
- 未做认证鉴权，仅限内网/演示用途。
